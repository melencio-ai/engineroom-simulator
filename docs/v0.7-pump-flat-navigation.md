# Engine Watch 3D v0.7 — Pump Flat and navigation hardening

Status: **feature build for Windows PPSSPP verification**. Base: `feature/psp-v0.6-reusable-ship-components`.

This remains an educational, fictional merchant-vessel arrangement. Pipework appearance, valve positions, instrument indication, clearances, material finishes and component dimensions are **illustrative**, not approved shipyard GA drawings or operational instructions. The v0.6 catalog's 33 reusable 3D component templates and 16 finishes remain the foundation.

## Work delivered

1. **Continuous walking collision:** each rendered frame's requested movement is subdivided into no more than eight horizontal slices, each approximately 0.065 m. X and Z are resolved independently to preserve wall sliding and physically walkable inclined ladders. This helps avoid passing through narrow landing/valve colliders.
2. **Headroom under inclined ladders:** a lightweight clearance query checks the visible stair underside at the player X/Z and relevant five-level stacking height. A candidate standing surface is rejected if a stair underside intersects the eye/head envelope. No expensive per-vertex collision or PSP physics engine is introduced.
3. **LO pump skids:** both low-poly pump/motor assemblies have added motor ribs, coupling guards, foundation feet and locally identifiable bolt heads.
4. **LO manifold:** the two local pump discharge risers join an overhead transverse header. It is built from the existing reusable `PipeSpool`, `PipeTee`, `PipeElbow90`, `WeldNeckFlange`, `PipeGasket`, `HexBolt`, `PipeSupport` and `PressureGauge` templates, with short illustrative LO identification bands. The main pump and standby pump remain independently controllable.
5. **Mission feedback:** pump-starting, running, pressure-building, and ECR-return hints are distinguished; the local control UI reports the illustrative common-header pressure and electrical bus status.
6. **CI:** headroom, existing complete ladder traversal, two-pump assembly, and unobstructed local control approach are checked in automated native tests. The pipeline still builds PSP and desktop binaries and runs a PPSSPP boot/framebuffer smoke test.

## Windows PPSSPP manual acceptance

Download the `engine-watch-psp-v0.7-pump-flat-navigation` artifact from a successful run of `.github/workflows/build.yml` on this branch. Extract `PSP/GAME/ENGINEWATCH/EBOOT.PBP` and place it in the emulator's ENGINEWATCH game directory, replacing a backed-up older EBOOT. Start a **fresh game**, not an older save-state.

- [ ] From the ECR, turn through its door, walk to the forward service ladder and descend deck 04 → 03 → 02 → 01 → 00 without falling or getting blocked.
- [ ] Return upward, including the lower and upper landings; camera must never pass through floor plates, stair treads or large underside geometry.
- [ ] Check the *aft alternative staircase* on all levels. Look at nearby bulkheads and overhead structure while turning.
- [ ] Approach the Deck 01 LO control panel from the passage at X≈2.64, Z≈-2.81. Cross/X opens the panel; six pump/valve actions remain selectable.
- [ ] Start the main LO pump; expect STARTING then RUN after the simulated short delay. Watch common-header pressure rise toward the illustrative 4.4 bar.
- [ ] Return to the Deck 04 ECR, verify mission 001, then test mission 002 strainer restriction and standby pump changeover. Confirm no regression.
- [ ] Inspect both pump skids and the overhead LO header for disconnected-looking joints, intersecting treads, mirrored fittings, unexpectedly floating gauges or unreadable safety routes.
- [ ] On actual PSP hardware or PPSSPP with PSP GPU profiling, check rendering speed and memory budget. A CI boot screenshot is **not** a full gameplay QA result.

## Technical constraints and next iteration

The scene still uses vertex-coloured triangles and procedural low-polygon models. Pump equipment status is shown in the HUD, **not** by animating 3D equipment yet. The new overhead LO layout is visual and not a pressure-network solver; the process state is held in `EngineSimulation`.

The next realism tasks should be (1) measured camera/fixture collision QA from recorded test footage, (2) manufacturer-based pump and couplings dimensions, (3) correct naval-architectural piping routing from an actual GA/P&ID, (4) texture/letter atlases for equipment identifiers, and (5) localized machinery and walking audio.

**Release gate:** do not merge this feature into v0.6, develop, or main without review of a playable Windows PPSSPP run and the user's approval.
